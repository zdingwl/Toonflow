# 资产视觉设计 Skill（所有资产提示词的事实层）

内部设计记录先整理剧本明确事实，必要的创作补全标注“设计补全”，未知项目标注“待确认”；这些来源与审核标注不进入最终图片提示词。不可捏造精确年龄、身高、左右位置、色值、伤疤、配饰或剧情。输出给图像模型的自然语言可去重，但不得丢失下述事实及状态约束。

## 资产绘制与视频引用分工

资产图片提示词是完整的可见设计：角色的身份、发型、服装和当前状态，场景的空间结构，或道具/生物的外形与材质必须足够清楚。只合并同义重复，不把必要定义缩成“同参考图”。审核按完整图片目标检查，不因视频采用短引用句就降低资产图的设计要求。

视频提示词使用已选图片的可见事实作简短绑定，动作、位置、镜头和互动属于视频内容；不复制资产绘制全文、展示板排版和静态外观清单。尚未生成或采用的资产 prompt 不能覆盖当前已选图片。

角色四视图是一张同一角色、同一状态的展示板，从左到右为脸部特写、正面全身、90°左侧面全身、正后方全身。独立渲染时每个子任务只画一个角色的一种视角，最后拼板。H3 使用从展示板保存的真实独立裁切，按实际分配的固定 Picture 顺序绑定同一个 Subject；展示板中的四个视角不代表四个角色，也不要求每个镜头上传全部视角。

场景默认一张空间关系完整的单画面；道具和生物默认一个主体的清晰单画面主视图。仅用户事实明确要求时才使用多视图，同一资产的不同视角不变成多个实体。生物保留活体结构和自然姿态，不套用无生命道具的静物或持握描述。既有选图和历史多视图资产不因本规范自动替换。

## 全局表现约束先于外观继承

资产提取的 desc/describe、资产设计及 prompt 都是后续绘制依据，不是原文引文。遵守 `global_content_constraints.md`：保留“受伤、遭到攻击、灾变”等剧情事实，不照抄红色血液、红色伤口或被血染红的环境。此项是固定的视觉改编规则，不属于无依据新增设定；禁止以“事实优先、状态继承、颜色不变”为理由恢复红色血液。

- 场景：把血色海水、染红的地面等改为自然环境颜色和受损痕迹；同步修正水面反射、反弹光及色彩基调，不能只删除“血”字却保留暗红海面。
- 角色：保留受伤部位与剧情后果，优先衣物遮挡、干净包扎、疼痛动作；必要的少量血迹明确为绿色或黑色。保持同一事件、资产及衍生状态一致。
- 道具：通过破损、磨损表达经历；情节必需的少量血迹明确为绿色或黑色，不能只写“染血”让模型自行补红色。
- 已指定绿色或黑色时沿用；未指定且必须表现时统一低饱和深绿色。红衣、红灯、红瞳、锈蚀、自然唇色等非血液特征保持原设定。
- 若任务确实要求引用原文，只在来源说明中忠实引用；供绘制的描述和提示词必须采用改编后的可见画面，不混写原文的红色要求。

## 角色：三层且不得混写

1. **身份 identity**：父资产 ID、角色名；稳定脸型、五官相对位置、基础发际线、肤色、体型与身份标志。一个身份只对应一个父资产；不把变身后临时的红瞳、湿身、伤痕、服装或海水特效永久写入身份层。
2. **状态 state**：父资产 ID、状态名、来源片段、触发条件、持续区间、改变字段和保持不变字段。状态可以显式覆盖身份中“可变”的默认属性，例如剧情明确的瞳色、形体、发型、服装；未列入改变字段的属性沿用基础身份。状态互斥时明确写出 `不可与普通态同时使用`，禁止以父资产图和衍生图作为同一时刻的两名角色并列引用。
3. **镜头 shot**：表情、姿态、动作、视角、短时光效和环境互动；这些不能自动回写成永久身份，也不因剧情短促而强制创建衍生资产。

**资产级状态判定**：只要视觉差异显著、不能稳定用镜头提示词表达，且该状态是一个关键叙事事件的必要视觉锚点，即使只出现一场/一镜，也允许创建可复用状态资产。纯特写/瞬时表情不创建独立状态。普通态与觉醒态在镜头引用时只能选一个有效形态；共享同一人物身份但不混用两份全身外观。

## 参考来源与目标状态

- 渲染风格由当前视觉手册与明确用户目标确定。旧图用于身份、衣装和状态继承，其旧有皮肤着色、背景及渲染方式不能压过本次风格目标。调整插画明暗与材质表达不等于换人或换装，审核须区分身份事实和画风；不得借风格参考搬入示例人物的发色、铠甲、武器或装饰。

- 先执行全局表现约束及本次资产类型的输出布局要求。当前 `describe` 中本次生效的明确目标事实优先于旧图对应字段；衍生角色继承父角色的明确身份事实和未被目标状态覆盖的属性。图片只补充这些事实未规定的可观察细节，不能覆盖角色身份或删除明确物资。旧图与目标不同正是本次需修正的内容，不等于目标无法生成。
- 本次要求的四栏、四宫格或单画面等布局由当前资产规范决定。旧图只有三栏、裁切、缺视角，或没画出目标描述中的对象，都不阻塞新提示词；按规范重组布局并保留明确内容，不要求先得到正确新图才能编写新提示词。
- 当前明确确认的发型、整套衣装与遮挡要求属于资产目标事实，必须保存在该资产描述中；不能只写在全局画风或临时聊天里，也不能推广为所有角色的穿着。生成时逐项遵循目标，旧图仅补充未规定字段。标志的位置保持一致，但可见性依衣袖、头发、视角而变化，不为露脸部痣或旧伤改变服装与构图。

- **画风示例图**只提供建模精度、人体比例、皮肤/发丝/衣料质感与布光，不提供本角色的脸、发型、衣装或身份。只有明确标为画风示例的图片才适用“不复制示例人物外貌”。
- **当前资产图 `actualReference`**是现有外观的可观察证据，不是生成目标的最终裁决。基础资产用它补充目标未规定的脸型、发型、衣装剪裁、材质等细节；目标已明确的瞳色、身份标志、物件及其他字段按目标生成，即使旧图颜色不同、被衣袖遮挡或没有画出。不能把图中缺失误当目标事实不存在。衍生资产的旧图与旧 prompt 只是历史生成结果，不具有覆盖父身份或本次目标事实的权威；未经目标授权的换装、发型、纹路、配饰和材质不得继续继承。
- **父角色图 `parentReference`**为衍生资产提供身份与基础衣装的视觉依据。父角色明确身份事实优先于父图对应字段，父图补充未规定细节；本次目标状态明确列出的变化可以覆盖对应可变项目，其他身份与衣装保持一致。不能借修正旧图换成另一个人物。父图不代表目标状态已经生成，不可把互斥的父态和目标态合成同一套外观。
- **状态文本 `derivativeStates`**用于区分该身份的其他状态、发生条件与可见变化，不是当前资产的外观清单。父资产描述若包含“以后/觉醒后/变身为”等剧情，或相关变化已归属于独立衍生态，基础态不继承未来的红瞳、湿衣、异形体、能源或海水特效。生成衍生态时也只采用当前指定状态的变化，不叠加其他兄弟状态。
- 遵守调用方提供的 **`referencePolicy`**：区分首次设计、当前图核验与父图继承。首次创建基础资产没有当前图时，按已知事实和明确标注的设计补全建立设计；首次创建衍生态没有目标图时，允许用父图继承身份，并按目标状态事实设计变化，不得因尚未生成目标图而形成循环依赖。调用方也可能有意不提供旧错误衍生图与旧 prompt；只要父身份和目标变化足够明确，就能完成衍生设计，不要求重新取得旧错误结果。
- 图片中模糊、遮挡或缺失的细节若已有明确目标事实，直接按事实生成；没有事实时不把模糊纹理臆认为瞳色、左右位置、伤疤、纹样或配件。普通未指定细节可保持不细写，不因旧图看不清就停止整个目标。只有必要父身份依据缺失、归属不明而不能可靠继承时，才说明具体缺失项，不能编造一个新身份。

## 场景与道具

- 场景保存固定空间结构：出入口、主通道和左右分区、前中后景的拓扑、主要物品相对位置、建筑比例、基准材质与照明。日夜、天气、损坏、灾害等显著且需跨镜头复用的状态单独记录；镜头角度不是状态。
- 道具保存造型、材质、颜色、尺寸关系、功能结构；生物保存物种、身体结构、体表材质和可辨识外形。使用姿态、短时动作和局部镜头属于 shot。必要的损坏/变形/功能状态应说明来源和持续区间，不得凭空生成额外物件或个体。

## 输出验收与可追踪性

- 为身份/状态分别保留对应资产 ID、来源片段、参考图路径或“待生成”标志。已有目标状态图用于当前外观核验；首次生成没有目标图时按上述来源规则建立设计，不能冒称已经存在目标图或已完成视觉核验。
- 区分两类冲突：**仅旧衍生图或旧 prompt 与父图及本次目标事实冲突**，且父身份与目标变化足以确定时，直接依据父图继承并应用明确变化，生成修正后的最终正文；舍弃旧结果中未经授权的外观，不以旧错误结果不同为由返回待核对。恢复父身份和未变衣装不属于新增剧情设定。
- **只有同一生效目标内部存在无法按状态与来源消解的互斥事实，或缺失/无法确定完成继承所必需的父身份依据**，才在调用方指定的内部审核字段返回具体冲突或缺失项；未解决前不补猜最终绘制指令。明确目标与旧图对应字段不同不属于此类问题，应按目标修正。描述明确的物资或标志不因旧图未画出而删掉，旧布局也不触发待核对。审核原因不混进绘制正文。全局表现约束按既定改编规则执行，不把被禁止的红色血液恢复为待选项。
- 检查相邻镜头相同身份的一致性与每镜只出现一个生效外观状态；检查场景拓扑不随镜头改变。
- 图片生成的外观描述使用可观察特征，不靠“高质量、震撼、精致”等抽象词代替具体设计。
