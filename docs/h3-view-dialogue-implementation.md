# H3 四视图与对白语言升级（实施记录）

## 已确认的产品方案

1. 四视图质量由用户人工确认，不新增强制的 AI 美术审查。标准四栏依次是脸部、正面全身、90°侧面全身、背面全身。
2. H3 可使用完整四视图 BOARD（一张 Picture、同一角色一个 Subject），也可根据镜头角度选择独立视图，或手动指定视图。互斥人物形态不能混用。
3. 生成提示词时可选择 `original`、普通话、美式/英式英语、日语、韩语、法语、德语、西语、俄语、巴西葡语等。只翻译对白与发声旁白；剧本原文保留在原分镜数据中。不同地区口音属于提示词要求，不保证视频模型绝对正确发音。
4. 翻译后重估受影响镜头的对白时长。能在原时长内完成则不延长；超出则显式报错，请用户局部精简或拆镜，不自动改整集总时长。
5. 提示词与最终视频任务共享同一个参考图解析器：资产身份、当前形态、图片内容指纹、视图顺序及 Picture 编号形成绑定。若素材/设置变化，拒绝旧提示词。

## 已提交到本 PR 分支的实现

- `h3ReferenceSlots.ts`、`assetReferenceMedia.ts`：完整 BOARD 默认一图；明确选择时按标准四栏提取 FACE、FRONT、SIDE、BACK。输入由用户审核，不新增美术自动质检。
- `h3GenerationContract.ts`：单条和批量共用 `prepareH3ReferencePlan`。基于项目归属、人物互斥关系、素材二进制指纹、视图及实际排序计算 SHA-256 摘要；在提示词中保存 `[TOONFLOW-H3-REFERENCE-V1:...]`，上传到 H3 前核对并移除该内部标识。旧提示词须重新生成。
- `h3DialogueLanguage.ts` 与 `minimaxH3Multi-referenceMode.md`：语言地区选项、保留原剧本、翻译对白要求及自然朗读预算基础估算。字幕/画面说明不跟着翻译；一名角色的所有视图归属一个 Subject。
- 工作台 `generate/index.vue`、`modeMenu.vue`、`track.vue` 与类型定义：增加语言、完整四视图/根据**明确选择的镜头角度**分配视图、手动视图选择。设置分别传入单条与批量提示词、视频生成接口。最近一次选择按项目/集保存于本机前端设置；换语言或换视图后须重新生成提示词。
- `generateVideoPrompt.ts`、`batchGeneratePrompt.ts`、`generateVideo.ts`、`batchGenerateVideo.ts`：提示词和执行端调用同一参考图计划；后端检查 Picture 个数、完整六段结构与翻译后发声文本的粗略朗读预算。视频执行前验证原素材指纹与顺序；批量任务先整体预检再创建视频记录。原始脚本不被覆盖。
- `.github/workflows/h3-feature-checks.yml`：PR 分支独立执行 `yarn test:agent`、后端 `yarn lint` 和前端编译。

## 当前限制与上线前验收

- 按镜头角度的选图逻辑需要当前镜头的**明确角度设置**（正面、侧面、背面、转身、特写）；暂不自动理解任意自然语言分镜的所有角度变化。未知角度会退回 BOARD；多个角色默认共享当前镜头角度，单个角色的独立覆盖可在上传素材配置中传递。
- 语言和视图的工具栏默认是当前项目/集最近一次选择，不是服务端永久存储的每条轨道配置；同一批次采用提交时的选择。单条提示词仍保存在对应轨道，运行前的图片绑定会检查变化。切换语言后需要手动重新生成该条提示词。
- 超出时长目前会返回错误及建议，**不会自动重新拆镜、翻译出多种候选译文或自动调整整集时长**。朗读时长是启发式估算，不等同于生成音频或可靠的精确口型校验。`original` 不强行根据未知语种估时。
- H3 多参提示词已为带有效参考图片的 Ref2VA 选择六段模板；无图片的文本模式、首尾帧模式，以及音频/视频参考等混合输入仍需单独按真实 ComfyUI 节点支持范围实测，不应拿本次身份参考绑定冒充首尾帧锚点。
- 需要独立验证：正常/觉醒角色、纯侧身、背影、转身、两角色、多资产不超过九图、旧提示词拒绝、换图指纹失效、翻译后超时提示、批量预检，以及原始视频与高清输出的音画一致性。
- 尚未在用户 Windows 的 ComfyUI 及真实 MiniMax H3 模型上做端到端生成测试。即使 GitHub CI 通过，也不能证明角色连续帧不会漂移或每种语言都能准确发声。
