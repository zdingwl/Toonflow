# Toonflow Skill 优化分析与验证

2026年10月8日。项目技能应让剧本、资产、分镜和模型提示词使用同一套事实与执行契约。本次清点 `data/skills` 的273份 Markdown，重点修正13份核心技能、H3模板及其加载与分镜同步代码，覆盖长文本读取、模式路由、参考绑定、时长和保存回执。画风与题材的专属创作内容保持原有组织方式。

## 资料与适配原则

[Anthropic 技能编写指南](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices)建议技能入口简洁、描述说明适用任务，并按需加载参考。本项目采用自己的 Markdown 加载器，因此保留已有 `.md` 文件名、技能名称和 `driector_skills` 目录，通过实际激活工具实现按需发现，避免直接套用其他平台的目录规范。

[Qwen 图像编辑文档](https://www.alibabacloud.com/help/en/model-studio/qwen-image-edit-guide)说明图片编号与输入顺序对应，多个参考可分别提供身份、衣装或姿态。本项目按本地代码的实际 `referenceList` 传递顺序绑定分镜参考；云接口的参数、图片数量和输出能力不能直接推定为本地工作流能力。

[MiniMax H3 官方参考模式指南](https://huggingface.co/MiniMaxAI/MiniMax-H3/blob/main/docs/VIDEO_PROMPT_WRITING_GUIDE_ref_en.md)区分可复用内容与参考文件，使用六节结构记录来源、保留关系、画面与声音。本次保留现有H3结构、身份及渲染继承规则，补足本项目整张人物参考图占一个图片位置、状态唯一和制作预算的约束；不增加固定提示词字数配额。

## 发现与修正

| 原问题 | 优化后的行为 |
|---|---|
| 导演规划只许读取一次，后续所有读取都被禁止 | 使用正确对象参数；完整读取后不重复拉取，分页可续读到 `nextOffset=null` |
| 分镜表使用片段标题，面板只认组标题；面板把场级资产传给每组 | 当前按片段写入，兼容历史组标题；使用片段实际引用，避免同人物不同状态混用 |
| 面板同时介绍三个模式，却没有故事板辅助多参流程 | 明确支持多参与逐镜首帧；不生成占位描述，也不冒称尾帧已完成 |
| 面板原文前新增承接句，破坏后续修订的精确匹配 | 多参直接复制完整片段；连续性问题回到分镜表修订 |
| 多场解析把下一场场头并入上一片段 | 场头终止上一片段，修订可匹配已保存面板，保留已有视频选择 |
| 通用图片技法强制光影段、Gemini JSON、负向字段和两个限定模型 | 格式与模型能力服从实际调用契约；面板沿用场景照明，保留剧情发光事件 |
| 画面左右被锁死为全场同一侧 | 保持世界位置、轴线和动作连续，按当前机位推导屏幕左右 |
| 纯屏幕文字被当作VO，审核强制添加点亮、滴答声等效果 | 区分发声与可见文字；只使用剧本或已确认分镜要求的效果 |
| 中文字数公式套用于其他语言；6、8、12秒及字数经验值被当硬上限 | 优先实际配音与制作预算，经验值作初估；并行动作与对白共用时间 |
| 剧本篇幅和自检固定为1000字、竖屏 | 篇幅服从内容和已确认时长，构图遵循项目画幅 |
| 技能元数据的多行值可能吞掉后续字段；同名技能被静默覆盖 | 修正块值边界，选中集合中重名直接报错，元数据XML字符转义 |
| 首次激活就列出其他已选风格资源，公共索引重复注入 | 仅发现实际激活技能所属风格的资源，同一调用工具集合去重索引 |

失败重试使用原 `requestId` 与相同业务参数，已确认完成的单位不重放。XML输出、任务发起、面板保存与图片/视频完成分别报告；监督层继续只审核，版本冲突和整集重建继续保留原授权边界。

以上验证证明加载和执行协议的可用性，不证明模型生成的画面质量。没有重新生成项目图片或视频，也没有改动生产数据库、旧任务快照或已有生成结果。

## 使用与后续验收

技能正文通过磁盘读取，并按 `runId` 保存快照：新的Agent运行读取新版技能，已经读取过旧技能的恢复任务继续使用其快照，不能为了应用更新清空历史快照。加载器和多场同步代码的更新需在部署后端源码或重新构建服务后生效；本次未重启现有服务。

后续模型验收应使用获准的独立测试任务，至少覆盖长剧本、横屏、非中文对白、两角色反打、同人物状态切换和缺参考图。核对真实工具参数、持久化回执及最终图片/视频；特别关注人物身份、身体支撑、图序与屏幕文字。生成成功或静态规则匹配不等于视觉验收通过。
