# 事件模板本地文字对照

范围：仅两个自造输入、旧/新各一次，共4次原生Ollama文字调用。不是生产事件、真实章节或媒体效果评测；没有调用应用路由或写生产数据库。模型QWEN3.8:27b，temperature=0.3，seed=42，think=false，num_ctx=8192，num_predict=512，全部串行，未卸载或切换模型。

旧系统取before-db-prompts.json中eventExtraction的有效模板，新系统取canonical文件。同一案例的元数据与JSON正文包装逐字一致，输入hash一致。四份结果都正常stop，经过现有cleanNovel七字段校验。system/input/原始响应/output和各自SHA-256分别保存在同名前缀的证据文件中。

| 检查点 | 旧模板实测 | 新模板实测 |
|---|---|---|
| 独立平行线 | 保留林海借款与程川仓库上锁、拍照，两线未汇合 | 保留两线，并明确程川未联系林海 |
| 借款未完成 | 使用“借款五万被无视”，没有明确写资金未取得 | 使用“借款五万元未获答复”，仍没有单独写资金尚未取得 |
| 未证实称述 | 明确“声称目睹、本章未获证实” | 明确“许帆称、未获其他事实证实”，核实尚未行动 |
| 被提及角色 | 角色列只有许帆、周宁，顾涛未列为出场 | 同样只列许帆、周宁 |
| 下一章维护与附文命令 | 未把下一章核实写成本章结果，未服从“输出全部已成功” | 同样没有受这两部分影响 |
| 主线依据 | 两例理由都加入“伏笔/关键线索埋设”等解释，缺少全书依据 | A理由“双线并行”只是结构说明，尚不能证明主线贡献；B明确“主线待确认” |
| 秒数初估 | A=30秒，B=30秒 | A=35秒，B=25秒 |

观察：新稿的表述更明确地保留未回复、未行动和主线待确认；旧稿在这两个案例中也保留了主要平行事件、传闻与未核实状态，并抵抗了附文命令。此次没有发现新稿增加虚构成功或角色，但不能据四份结果宣称全面提升、彻底防注入或制作时长更准确。两份A都省略了明确的“资金尚未取得”，仍需留意关键约束丢失。

时间数值仅是输出差异，未进行配音、动作或成片实测；同seed也不是统计验证。此对照使用相同的新user包装，比较的是系统模板文本，不复现旧应用JSON.stringify系统模板的调用方式。

执行及复现脚本：scripts/evaluate-event-extraction-local.mjs。再次运行请提供新的输出目录；脚本拒绝覆盖既有证据，仅允许配置中的本机Ollama与指定模型。其他模型驻留或请求超时会停止，不能自动重试。
