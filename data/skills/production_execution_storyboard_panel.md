# 分镜面板写入

仅将已完成且已获准使用的分镜表转为面板，不重做剧本、导演规划或分镜表，不在此阶段发起图片/视频生成。

## 读取与模式选择

- 调用 `get_flowData({key:"storyboardTable"})`、`get_flowData({key:"assets"})`、`get_flowData({key:"storyboard"})`，按需读取 `{key:"script"}` 核对内容。带分页参数时按 `nextOffset` 续读到 `null`；不能把一页当全表。
- 模式取自派发指令和当前项目模型/多参配置。明确冲突或模式缺失且无法确定时返回具体缺项，不自行切换。多参进入流程 A；“首帧 / 首尾帧 / 首位帧”进入流程 C。本工具只写一条 `prompt`，此阶段产物是首帧参考，不能声称尾帧已生成。
- 当前版本没有独立的“故事板辅助多参”写入流程；收到该要求时报告缺少支持，不写固定占位描述或冒充已完成。
- 已有面板时先核对本次范围与已保存内容。保持已有图片、视频和人工编辑；已确认完成的单位跳过。无法确定已有单位与新表的一一映射时返回冲突，不通过重复新增来替代修改或重建。

## 流程 A：多参片段写入

不生成 `prompt`，不激活图片技法。一个已分好的片段写入一条面板，不自行合并或重新拆段。

1. 当前表使用 `## 场N` → `### 片段…（约Ns）` → 引用资产 → 镜头表。兼容历史 `### 第N组` 标题，二者均表示写入单位，不要求场级资产清单。
2. `videoDesc` 完整复制该单位从片段/组标题开始的全部原文，包括已有片段意图、起止状态、引用资产名称/ID、表头与数据行，保留原顺序和文字。旧表没有片段意图仍可使用；不在面板阶段补写意图、添加“承接上镜”前缀、风格词或创作说明。动作衔接由源表事实承载，缺少必要连续性时反馈上游修订，不自行推导新剧情。
3. `associateAssetsIds` 取本片段的真实资产 ID，按原引用顺序去重。不得把同场所有角色状态都复制到每个片段；历史表仅有场级清单时，对照该单位实际入画内容核对，歧义先反馈。互斥状态不能同时引用。
4. `duration` 取本单位镜头时长之和，并与标题数值核对；缺时长、合计矛盾或超过 15 秒时停止该单位写入，报告具体问题，不用“约”掩盖冲突。
5. `track` 为跨场连续递增的字符串序号；`prompt:null`，`shouldGenerateImage:"false"`。逐单位调用写入工具，核对成功回执后再继续。

## 流程 C：逐镜首帧写入

激活 `storyboard_prompt_techniques` 与已选画风的 `director_storyboard`，只读取当前任务需要的资源。技法服从全局约束、任务模式、真实参考与分镜事实；风格参考不能覆盖身份、剧情、画幅、时长或工具格式。

1. 每条镜头数据行写入一条面板，不把表头、场标题或分隔行算镜头。`duration` 原样取本行秒数；`track` 跨场按行递增。
2. 根据本行实际可见角色、场景和道具，从片段清单核对真实 ID，形成 `associateAssetsIds`；只绑定当前有效状态。作为 `@图N` 引用的资产须已有可用图片，缺图时先反馈，不让后端跳过图片后造成编号错位。
3. `prompt` 只描述本镜首帧：先理解本行在片段意图中的任务，再把它落实为首帧可见的主体、构图、视线和姿态，不把意图说明写成画中文字。已静止的姿态和表情直接保留，连续动作取语义合理的开始状态，镜头运动取起始构图。保留施力者、接触点、身体支撑、相对位置、视线和可见界面文字，不把所有动作机械改成“即将”。图片不承载台词、声音、时间轴或整个动作过程。
4. 参考编号严格跟随本条 `associateAssetsIds` 的图片输入顺序，从 `@图1` 开始；ID 不是图序号。前缀说明“@图N 为资产名称与类型”，正文用对应标记指向参考。局部/背影依然属于该人物，不创造第二个角色。
5. 连续镜头延续世界坐标、动作进度、接触关系与视线。画面左右由本镜机位决定：反打或合理机位变化可改变屏幕位置，不能机械锁定全场同一左/右位置；没有转身动作时，不仅为换景别改变身体朝向。
6. `videoDesc` 保留本行的画面、场景、名称/ID、时长、景别、运镜、动作、朝向/空间关系、情绪、台词与音效。旧表没有独立动作/朝向列时从画面描述读取，不编造列值。`prompt` 按当前模型要求输出字符串；无指定 JSON 协议时使用自然语言。
7. 身份、衣装和空间结构来自有效参考，渲染目标沿用已确认的项目画风。照明符合本场时段、天气与场景已有光源，可用简短受光、阴影和材质描述落实电影表现，不凭空增加光源或改变场景状态；屏幕亮起、必要特效等原文事件保留。实际声源留在 `videoDesc`，不混入静态图片提示词，也不增添配乐。`shouldGenerateImage:"true"` 仅表示后续需要图片。

## 工具与保存协议

调用 `add_flowData_storyboard({videoDesc,prompt,track,duration,associateAssetsIds,shouldGenerateImage,requestId?})`，其中 `prompt` 为字符串或 `null`，`track` 为字符串，`duration` 为数值，`associateAssetsIds` 为真实 ID 数组，`shouldGenerateImage` 必须为字符串 `"true"` / `"false"`。

- 不再输出 `<storyboardItem>` XML。每个单位调用一次，工具返回失败不计入完成数；保存失败时保留已经成功的单位并报告中断位置。
- 超时或失败后，重试同一单位必须复用原工具错误中的 `requestId`，所有业务参数保持不变；不同单位不能共享同一标识。来源版本改变时停止旧请求，不绕过版本保护。
- 验收数量为流程 A 的片段数或流程 C 的镜头数据行数；时长逐单位和全片核对，图片顺序、ID、模式字段均需一致。
- 最终简短报告确认写入数量、跳过的已完成单位及未解决项。没有全部成功回执时不报告面板全部完成；面板写入成功也不代表图片或视频已生成。
