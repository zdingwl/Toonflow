# 短剧导演计划优化与试生成

本次针对 `http://localhost:50188/#/production` 的“生成导演计划”，实读了项目《重生三天，我囤爆整个海洋》第一集、页面保存的计划、运行中的后端、数据库与模型配置。调整的是导演规划及其向分镜交接的方式，未覆盖现有生产计划、分镜、资产或视频。

## 根因

旧主技能的主要任务是分场统计、情绪摘要和注意事项，限制了真正的导演设计。页面中的三场计划完整描述了“背叛—回溯—备战”，但未明确观众主导问题、信息揭示次序、可见表演节拍和三通电话的不同戏剧功能。

原调用只附统计事实，具体动作依赖模型主动读剧本；项目选择了 `Scifi_post_apocalypse`，但导演规划并未加载相应叙事规划技法。画幅、题材和完整来源没有共同进入导演任务。已有制作预算为25、22、62.5秒，与来源25、20、50秒分别保留。

通过公开网页和原作者仓库检索、阅读了以下类似方案，采用其方法重新写作本项目指令，没有整体安装外部工作流或执行仓库脚本。

## 改动

- `data/skills/production_execution_director_plan.md`：五部分输出——整集导演意图、原八列分场表、逐场导演设计、场间过渡、需确认问题。允许不改变剧情的表演与调度；每拍必须有来源、局势变化、可见行为及节奏理由。禁止新增成交结果、额外设备、道具和后续剧情，也不把动作标记改成台词。
- `src/agents/productionAgent/directorPlanContext.ts` 与 `index.ts`：直接附完整原文、画幅/题材、说话人原名、统计、每场0至预算的目标区间及已有连续性锚点。所选题材文件通过原任务快照读取，只注入主题与叙事结构部分，排除下游摄影、音乐章节；不读取全部17种题材。输入仍是数据，输出遵守唯一闭合 scriptPlan。
- 导演规划调用的温度上限设为0.6，已配置的更低值保留；其他智能体与模型选择未改，数据库部署配置未改。
- `screenplay.ts`：新版节拍从0连续覆盖各场预算；重叠、缺口或错误绝对时段会拒绝保存。旧版仅含分场表的计划保持兼容。拒绝后仍保留原分镜与视频。
- `production_execution_storyboard_table.md`：要求将导演节拍转换成有功能的镜头，保留铺垫、揭示、反应、后果和重要决定的停顿；一拍可多镜，不把节拍当作单次生成片段。
- `scripts/evaluate-director-plan.ts`：隔离文本评估，直接以只读连接读取当前数据库，使用已有配置的Ollama文本模型与只读工具，输出到独立目录；不导入应用初始化模块、不写生产数据库、不调用图片/视频生成。

## 实际试生成与复核

模型为当前配置的 `QWEN3.8:27b`，关闭思考，与页面选项一致。旧方案温度1，新方案最终温度0.6；评估请求固定seed42。这里比较的是整套调用方案，不是只改变提示词的严格单变量实验。

| 检查项 | 旧方案最终样例 | 新方案最终样例 |
|---|---|---|
| 内容组织 | 统计、注意事项、过渡 | 整集问题、钩子/推进/回报、逐场节拍、连续性和风险 |
| 场内有效节拍 | 未明确设计 | 4 / 3 / 5 拍，共12拍，各有来源、行动和节奏理由 |
| 场内区间 | 无 | 各从0起，合计25 / 22 / 62.5秒 |
| 台词条数/字数 | 4/24、2/6、5/60 | 完全保持 |
| XML及事实/预算校验 | 通过 | 通过 |
| 实测文本生成 | 8.8秒，1235字符 | 33.2秒，5833字符 |

新版样例把三通电话的功能区分为筹资、空间准备、物资询价，分别承接“确认新闻—系统资源—行动—宣言”的因果；开场用抓握、求助与掰指建立关系危机，水下规则揭示留确认窗口，结尾落在已启动但未完成的准备任务。复核最终样例没有早期版本的姓名混写、纸笔/平板、额外运输风险或虚构成交结果。

迭代记录均保留在 `docs/director-plan-evaluation/`：初版虽丰富了导演设计，但用了来源绝对时段，并出现无依据道具/姓名混写；第二版场内预算正确但未输出XML根；第三版协议和预算通过，仍有姓名漂移与冗长。最终版补足姓名表、紧凑写法、共享输出协议、聚焦题材参考与较低采样后再验证。早期文件是未采纳候选，不是合格生产结果。

最终样例：`episode-1-final.md`；对照样例：`episode-1-before-final.md`；相邻JSON文件记录模型、参数、耗时、只读工具与事实错误。样例单独保存在仓库中，尚未替换页面的旧计划。文本试生成不能证明实际成片或所有题材都达标，后续仍需当前的分镜审核与真实视频验收。
